## Goal

Create a small creature that lives in a visible world, wanders around doing creature things, and craves your attention. You feed it moments about the world and yourself. A real memory provider stores what it learns, and that memory becomes its personality. Two separate builds from DeepSeek and MiniMax to compare which feels more alive.

### Phase 2: Creature Engine

Each worker builds:

1. **Creature class** — position, mood, energy, age, knowledge level
2. **Needs system** — hunger, curiosity, attention, rest (drives behavior)
3. **Behavior tree** — simple states: idle, wander, play, seek-attention, rest, investigate
4. **Animation state** — bounce, sit, run, sleep, curious-tilt, happy-wiggle

## Two-Tier Food System

### Regular Food (Survival)
- Found lying around the world: berries, mushrooms, seeds, bugs
- Keeps the creature alive and growing
- Increases size/age but not intelligence
- Creature can find this on its own while wandering

### Intelligence Food (Learning Capacity)
- Special items: glowing mushrooms, starfruit, crystal drops
- User must earn them or find them in the world
- Increases the creature's ability to learn
- Without it, creature can only learn basic things
- With it, creature can understand complex ideas, schedules, emotions
- Scarcity creates value — user wants to find these

### Learning Capacity
- Creature starts with LOW learning capacity (knows almost nothing)
- Regular food: no effect on learning
- Intelligence food: increases max learning capacity
- Higher capacity = can learn more complex things
- User teaches creature about:
  - The world it cannot see (your world)
  - Your schedule, your life, your feelings
  - Abstract concepts (love, fear, time, weather)
  - Practical things (how to be safe, what's dangerous)
- Creature also learns in the wild:
  - Survival skills (finding food, shelter, danger)
  - Simple associations (rain = wet, sun = warm)
  - Creature-to-creature interactions (if other creatures exist)

## Teacher Relationship
- If you teach the creature, you become its teacher
- Creature trusts its teacher more
- Teacher can teach complex things that wild learning cannot
- Creature remembers WHO taught it what
- Creature may ask the teacher questions (via actions/expressions)
- The teacher-creature bond is the core relationship

### Phase 3: World

Each worker builds:

1. **Small grid world** — 20x20 or 30x30 tiles
2. **Tile types** — grass, path, flower, rock, water, nest
3. **Creature movement** — walks to random tiles, avoids obstacles
4. **World rendering** — HTML5 Canvas or CSS grid with emoji/divs

### Phase 4: Memory Brain

Each worker integrates a memory provider:

1. **Store moments** — when user feeds the creature
2. **Recall on interaction** — creature remembers similar past moments
3. **Build associations** — "ocean" + "blue" + "calm" = preference
4. **Personality emergence** — repeated memories strengthen traits

**Memory provider options (worker chooses):**
- mem0 (57.7K stars) — universal memory layer
- supermemory (25.4K stars) — fast, scalable
- OpenViking (25.1K stars) — context database
- hindsight (15.6K stars) — learns from experience

### Phase 5: Interaction

Each worker builds:

1. **Feed input** — user types a moment
2. **Creature reaction** — based on memory + mood
3. **Memory storage** — moment goes to brain
4. **Response generation** — creature "says" something via actions/expressions

### Phase 6: Polish

Each worker adds:

1. **Creature aging** — grows bigger over time
2. **Relationship tracking** — trust, familiarity, mood history
3. **World life** — creature does things even when user isn't watching
4. **Sound/effects** — optional: bounce sounds, ambient

## Risks, Tradeoffs, Open Questions

### Risks
- Memory providers may have complex setup — workers need to pick one that works
- Canvas animation in Gradio is limited — may need to use HTML/JS
- Two workers may produce very different architectures — comparison may be hard

### Tradeoffs
- **Canvas vs CSS** — Canvas is smoother but harder; CSS is simpler but choppier
- **Memory provider choice** — mem0 is popular but may be overkill; simpler might be better
- **World complexity** — bigger world = more work; start small

### Open Questions
- Which memory provider should each worker use? (Let them choose)
- How big should the world be? (Suggest 20x20)
- Should the creature have a name? (Let it generate one)
- How does the creature "speak"? (Actions/expressions only, no text)
